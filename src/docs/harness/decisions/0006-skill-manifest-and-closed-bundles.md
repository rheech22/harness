# 스킬 선언은 매니페스트 하나가 소유하고 번들은 닫혀 있어야 한다

## 배경

첫 프로토타입은 문서 frontmatter의 `skill`·`skill_description`으로 스킬을 선언했습니다. 한 스킬에 문서가 셋 들어가자 같은 설명이 세 파일에 중복됐고, 한 문서가 두 스킬에 들어가는 경우를 표현할 수 없었습니다. socra-tutor-fe의 `code-review.md`를 실제로 이식해 보니 문서 밖의 것이 함께 따라왔습니다. HTML 템플릿과 라이선스 파일, 상대 링크 36개, 프로젝트마다 다른 값(base ref, 자동 검사 표, 리포트 경로)입니다. 번들로 복사되는 순간 링크는 전부 깨졌습니다.

## 결정

- 스킬 하나는 `src/skills/<name>.json` 하나가 선언합니다. `description`, 읽기 순서를 가진 `reads`, `assets`, `scripts`, `profile`, `commands`를 담습니다. 문서 frontmatter에는 스킬 정보를 두지 않습니다.
- 번들은 닫혀 있어야 합니다. `build`가 문서의 상대 링크를 번들 기준으로 다시 씁니다. 번들 안 대상은 `references/`·`assets/`·`scripts/` 상대 경로로, 번들 밖의 하네스 파일은 저장소 URL로 바꾸며 경고를 남기고, 존재하지 않는 대상은 빌드 오류입니다.
- 프로젝트마다 달라지는 값은 프로필로 뺍니다. 선언이 기본값 문서와 프로젝트 쪽 경로를 가리키고, 생성된 `SKILL.md`가 프로젝트 파일 읽기를 첫 단계로 강제하며 어느 프로필을 썼는지 보고하게 합니다.
- Claude slash command는 선언의 `commands`에서 생성합니다. 어댑터 폴더에는 정책이 아닌 배선만 남습니다.

## 고려한 대안

- **frontmatter 선언 유지 + 첫 문서만 설명을 가짐**: 중복은 줄지만 "어느 문서가 첫 문서인가"가 암묵적이고, 읽기 순서와 자산 목록을 둘 자리가 없습니다.
- **링크를 재작성하지 않고 번들 밖 문서를 전이적으로 전부 포함**: 번들이 커지고 어디서 끝나는지 알 수 없습니다. 밖을 가리키는 링크는 URL로 남기되 경고로 드러내는 쪽이 경계를 유지합니다.
- **프로필을 문서 본문의 "프로젝트에 따라 다름" 문장으로 대체**: 모델이 값을 추측합니다. 실제 검증에서 프로젝트 프로필 파일이 있는데도 "없다"고 답한 사례가 있어, 읽기를 첫 단계로 강제하고 보고 줄을 요구하는 형태로 바꿨습니다.

## 영향

`build`가 선언을 읽는 생성기가 됐고 `check`가 번들 닫힘을 검사합니다. 이식 작업은 "원문 복사 → 끊어진 링크를 빌드가 알려 줌 → 프로젝트 고유 절을 프로필로 분리"의 반복이 됩니다. 2026-11-08에 `code-review`를 이 흐름으로 이식해 새 Claude 세션에서 `/review`가 번들만으로 HTML 리포트를 만드는 것까지 확인했습니다. 경로 조건 규칙(`adapters/claude/rules/*.md`)은 아직 손으로 쓴 정책이라 같은 방식의 생성 대상으로 남아 있습니다.

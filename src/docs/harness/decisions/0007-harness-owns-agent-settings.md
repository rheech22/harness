# 에이전트 설정을 하네스가 관리하고 로컬 파일에 적용한다

## 배경

에이전트 지침과 스킬은 하네스가 관리하지만 Claude settings와 훅 일부는 dotfiles가 관리했습니다. 사용자는 설정을 여러 저장소에서 찾고, dotfiles가 없는 사용자는 설치 절차를 완성하기 어려웠습니다. settings는 앱과 플러그인도 수정하므로 전체 파일을 원본에 링크하면 외부 변경이 설정 원본에 들어옵니다.

## 결정

사용자 합의에 따라 에이전트 설정 원본과 로컬 적용 절차를 하네스에서 관리합니다. dotfiles는 선택적인 프로그램 설치 수단이며 하네스 실행의 사전 조건이 아닙니다.

일반 지침·스킬·규칙은 `link`로 연결합니다. Claude settings와 기존 Codex 훅 등록은 `configure`로 로컬 JSON에 적용합니다. 적용 위치·원본·관리 기록 경로는 어댑터가 선언합니다. Codex `config.toml` 적용은 이 결정의 구현 범위에 포함하지 않습니다.

일반 설정은 leaf별로, 훅은 command별로 소유합니다. 다른 설정을 보존하고 충돌은 적용 전에 보고합니다. 기존 symlink는 명시적 이관 옵션으로만 일반 파일로 교체합니다. 이전 설정과 링크 정보를 백업하고, 적용 실패 시 복원합니다. 실제 체크아웃 위치는 로컬 적용 시에만 명령에 넣습니다.

## 고려한 대안

- dotfiles와 소유권을 계속 나누면 설정 원본과 설치 순서가 여러 곳에 남습니다.
- 사용자 설정 전체를 symlink하면 앱과 플러그인의 변경이 원본에 반영됩니다.
- 설정 전체를 덮어쓰면 외부 도구가 관리하는 항목을 잃습니다.

## 영향

하네스만으로 설정을 연결하고 적용할 수 있습니다. 로컬 관리 기록과 백업은 추가되지만 새 설정 원본을 만들지는 않습니다. 프로젝트별 설정과 인증·세션·캐시는 각 프로젝트와 런타임에 남습니다. dotfiles 재적용이 하네스 경로에 영향을 주지 않는지도 이관 시 검증해야 합니다.

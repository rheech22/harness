# 이전 프로젝트 문서 전체 추가 기록 (2026-11-08)

## 요약

code-review 추가으로 구조를 확정한 뒤, 추가 가능하다고 분류한 나머지 문서를 세 묶음(common, writing, web)으로 나눠 병렬로 들여왔습니다. 문서 20편, 프로필 9편, 리포트 자산 8파일과 검사 스크립트 2편, 문서 템플릿 3종이 추가됐고 스킬 선언은 16개가 됐습니다.

## 시간 순서

1. 세 묶음을 병렬 추가. 각 묶음은 같은 규칙을 받았습니다. frontmatter 고정 형식, 본문 보존, 프로젝트 고유 값은 프로필로, 링크는 존재할 파일에만, 나머지는 평문.
2. 추가 중 `build`에 경로 조건 규칙 생성(`rules`)을 추가하고, 손으로 쓴 `adapters/claude/rules/writing.md`와 `commands/review.md`를 제거. 어댑터 폴더에는 배선(`adapter.json`, `hooks.json`, 권한 규칙, `project/`)만 남음.
3. 스킬 선언 15개와 프로필(common 14, writing 2, web 4)을 작성.
4. 전체 빌드: 스킬 16개, 생성 파일 73개, 끊어진 링크 0, 번들 밖 링크 경고 45(저장소 URL로 재작성됨).
5. 번들 안 스크립트가 템플릿을 못 찾는 결함 발견. 소스 배치(`assets/report/scripts/../`)와 번들 배치(`scripts/../assets/`)가 달라서였고, 두 위치를 순서대로 찾도록 고침.
6. 가짜 HOME에 세 프로필을 모두 링크(42개)하고 Claude 새 세션으로 확인. custom 스킬 16개 발견, `.ts` 편집 시 생성 규칙 `coding.md` 주입, `/review`·`/explain` 노출.

## 들여온 것

| 도메인 | 문서 | 프로필 | 스킬 |
| --- | --- | --- | --- |
| common | code-style, testing, security, commit-messages, document-writing, documentation, document-review-workflow, worktrees (+ 기존 code-review, report-design, prose-style) | commit-messages, document-review (+ code-review) | coding-conventions, testing-conventions, git-commit, docs-writing, docs-review-loop, git-worktrees (+ code-review, codebase-onboarding) |
| writing | technical-explanation, report-diagrams (+ wiki-links) | technical-explanation | technical-explanation (+ wiki-link-curator) |
| web | fsd, tailwind, storybook, accessibility, wcag-criteria, animation-lifecycle | fsd, tailwind, storybook, accessibility | fsd-architecture, web-ui-conventions, storybook-conventions, web-accessibility |

생성 규칙 4개: `coding`(코드 파일), `testing`(테스트 파일), `writing`(Markdown), `storybook`(스토리). 생성 명령 2개: `/review`, `/explain`.

## 발견 사항

- 추가의 실제 작업은 "프로젝트 고유 절을 프로필로 떼는 것"이었고, 문서당 프로필 절은 2~10개였습니다. 프로필 절 제목이 프로젝트와의 계약이 됩니다.
- 병렬 추가에서 묶음 간 링크는 "존재할 파일 목록"을 미리 주면 깨지지 않았습니다. 끝나고 빌드가 전부 검증합니다.
- 규칙 파일은 문서 본문을 인라인하므로 길이가 항상-로드 비용입니다. 현재 104~188줄입니다.
- 번들 스크립트는 소스와 번들에서 상대 위치가 달라집니다. 스크립트는 두 배치를 모두 시도하거나, 번들 배치만 전제하고 소스에서도 같은 배치를 쓰도록 통일해야 합니다.
- 두고 간 것: research, figma, landing-pages, prototyping, lab, browser-verification, design-system, public-assets, 운영 가이드들. 이전 프로젝트의 디자인 시스템·인프라에 묶여 있어 걷어내면 내용이 남지 않습니다.

## 현재 상태

`check` 통과. Claude에서 발견·규칙·명령 확인. Codex에서 `$<skill>` 호출과 리포트 생성은 미검증. 추가된 문서의 프로필 기본값은 추가 작업자가 고른 중립값이라 실제 프로젝트에 붙일 때 한 번씩 검토해야 합니다.
